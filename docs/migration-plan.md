## 1. 소유자 결정 (2026-10-23 확정)

1. **스키마 이전 승인 — 양식 데이터 구조의 정본은 하나뿐이다.** 프로파일이 곧 스키마다. 읽기 열 위치, 내보내기 열 위치,
   헤더 줄 수, 지문, 내보내기 헤더, getter가 한 정의 안에 있고, 같은 사실을 두 곳에 적지 않는다(두 곳이면 반드시 갈라진다).
   정본은 `schema.js`에 둔다(별도 JSON 파일로 쪼개지 않는다). 상세는 §1-B.
   기존 양식의 열 매핑 값은 바꾸지 않고 형식만 옮기며, 옛 파서와 새 파서 결과 동일성을 테스트로 증명한다.
2. **4과목 합 규칙 변경 승인.** 값 = 국어 + 수학 + 탐구평균(탐구 1과목이면 그 값, 2과목이면 평균).
   - 평균은 **반올림하지 않고 그대로** 쓴다(표시만 소수 자리 제한 가능).
   - 국어·수학 중 하나라도 없으면 제외.
   - 탐구를 하나도 안 본 학생은 **기본 제외**하되,
     (a) 제외 인원을 화면에 문구로 남기고("탐구 미응시 N명은 합산 순위에서 제외됨"),
     (b) **"탐구 미응시 학생도 포함" 체크박스**를 둔다. 켜면 그 학생은 국어 + 수학만으로 순위에 들어간다
         (탐구평균 항 = 0이 아니라 '항 없음'. 문구로 명시).
   - 영어·한국사는 합산에 넣지 않는다(현행 유지).
   - **수능최저 표의 전교 석차도 같은 합산(국 + 수 + 탐구평균)을 쓴다**(2026-10-23 추가 결정).
     탐구1·2를 단순히 더하면 1과목 응시자가 원점수 기준 최대 50점 손해를 보기 때문이다.
     수능최저 표의 등급 n합(sum2~sum5)은 등급 기준이라 바뀌지 않는다.
   - 세부 규칙은 §1-A.
   - CLAUDE.md의 해당 문구를 먼저 고치고 코드를 고친다.
3. **보관 방식.** 메모리 + `.json` 프로젝트 파일 하나에 **모든 회차**를 담는다. IndexedDB 미사용. 원본 엑셀 미포함.
4. **회차 키와 순서.**
   - 키는 자유 문자열. `2026-03`, `3`, `사설` 모두 허용. 파일에서 추론한 값은 입력란에 미리 채우고 사람이 고친다.
   - 같은 키는 회차를 구분할 수 없으므로 중복 키는 막는다(예: 사설이 둘이면 `사설1`·`사설2`처럼 사람이 구분).
   - **순서는 키와 별개의 값(`order`)으로 둔다.** 키로 자동 정렬해 초기 순서를 제안하되
     (`YYYY-MM` > 숫자 월 > 그 밖의 문자열은 추가한 순서로 끝에), 사용자가 **위/아래 이동(또는 드래그)으로 순서를 바꿀 수 있다.**
     추이 차트·표의 가로축은 항상 이 `order`를 따른다. 순서도 `.json`에 저장된다.
5. **학생 동일인 식별.** 같은 학년 안에서만 잇는다: `학번` → `학년+반+번호`. 키가 같은데 이름이 다르면 잇지 않고 확인 대상으로 띄운다.
   **학년이 바뀐 회차 간 연결은 이번 범위에서 제외**하되 길만 열어 둔다: `identity.js`가
   "외부 대응표(나이스 반·번호 이력) → 동일인" 매핑을 받을 수 있는 입력 자리를 두고, 지금은 구현하지 않는다(우선순위 낮음, backlog).
   다른 학년 회차를 불러오는 것 자체는 막지 않는다.
6. **익명화 없음.** 이름을 그대로 표시한다.

## 1-A. 탐구평균 세부 규칙

목적: 탐구를 1과목만 본 학생이 합산에서 **손해를 보거나 누락되지 않게** 한다. 모든 규칙은 이 목적에서 나온다.

| # | 규칙 | 이유 |
|---|---|---|
| A1 | 기준(원/표/백)마다 따로 계산한다. 그 기준 값이 있는 탐구만 센다: 1개 → 그 값, 2개 → 평균, 0개 → 탐구 항 없음 | 탐구1은 표준점수가 있고 탐구2는 원점수만 있으면, 표준점수 기준에서는 탐구1 하나로 본다. 없는 값을 0으로 채우지 않는다(CLAUDE.md) |
| A2 | 등급 기준에는 적용하지 않는다 | 등급 합은 수능최저 n합 표의 영역이다 |
| A3 | 탐구1·2의 과목명이 같으면(`sameInquirySubject`) 탐구1 값 하나로 본다 | 같은 과목이 두 번 적힌 것은 자료 중복이지 2과목 응시가 아니다. 현행 선택과목 집계(report-cache.js:85)와 같은 판단 |
| A4 | 평균은 반올림하지 않는다. 동점 판정 키만 지금처럼 소수 6자리로 맞춘다(report-csat-sum.js:128 방식) | 2진 오차로 같은 점수가 다른 순위가 되는 것을 막는다 |
| A5 | 화면 표시: 원·표는 소수 1자리(평균에서 .5가 나오므로), 백은 현행대로 1자리. 학생 모달 합계(report-modal.js:124), 상위 N 표의 제목 "탐구1+탐구2"(report-render-topN.js:51)와 0자리 표시(:70)도 바꾼다 | 정수로 표시하면 서로 다른 점수가 같아 보인다 |
| A6 | 국어·수학 중 하나라도 그 기준 값이 없으면 합산 없음(순위·분포 제외) | 현행 규칙 유지 |
| A7 | 탐구 항이 없는 학생: 기본 제외 + "탐구 미응시 N명 제외" 문구. 체크박스를 켜면 국 + 수로 순위에 넣는다 | 결정 2 |
| A8 | 급간 분포는 현행처럼 최대값에서 구간을 동적으로 만든다(report-score-distribution.js:37). 소수 합은 `floor`로 구간에 넣고, 구간 라벨은 `min~max` 대신 "min 이상" 형식으로 바꾼다(report-score-distribution.js:46, 299.5 같은 값이 라벨 사이에 걸리지 않게). 체크박스로 들어온 국+수 학생은 분포에 섞되 "탐구 미응시 N명 포함 — 국+수만으로 계산되어 다른 학생과 같은 척도가 아님" 문구 | 상한은 300(원·표는 그 이상)으로 바뀌지만 구간 계산은 이미 최대값 기준이다 |
| A9 | 수능최저 표 전교 석차: 현행 `_getScoreSum`은 빈칸을 0으로 더하고 `|| 0`을 쓴다(report-csat-sum.js:69, 126 주석, 128). 같은 합산 함수로 바꾸면서 빈칸→0과 그 주석이 함께 사라진다 | 한 함수로 통일. 버그 수정은 커밋을 분리해 기록한다 |
| A10 | 수능최저 전교 석차의 대상·정렬: **원점수 합이 있으면 석차에 넣는다**(국어·수학 원점수는 원점수 열이 없을 때 `sumParts`로 만든 공통+선택 합을 포함). 정렬은 현행처럼 원→표→백 사전식이고, 표·백 합이 없는 학생은 그 비교 단계에서 맨 뒤로 간다. 동점은 세 키가 모두 같을 때(없음끼리는 같음으로 본다). 원점수 합이 없으면 제외. 체크박스와 "제외 N명" 문구는 이 표에도 똑같이 적용된다 | **가채점 등 원점수만 있는 회차가 흔하다.** 표·백 합이 없다는 이유로 빼면 그런 회차에서는 석차가 비어 버린다 |
| A11 | 원점수만 있는 회차(소유자 결정, 적용 화면은 §1-C): 기준(원/표/백)은 화면 전체에 하나이고, **회차를 바꿔도 자동으로 다른 기준으로 바꾸지 않는다.** 파일을 처음 불러올 때도 마찬가지로 바꾸지 않는다(2026-10-23 소유자 결정: 첫 로딩은 언제나 원점수). 고른 기준의 값이 없는 회차에서는 "이 회차에는 표준점수가 없어 표시할 수 없습니다"(백분위도 같은 형식)를 띄우고, 그 기준의 모든 숫자 자리를 **`—`(긴 대시, U+2014)**로 가린다. 다른 기준의 숫자를 대신 보여 주지 않는다. 추이 차트에서 그 기준 값이 없는 회차는 **빈 점(선 끊김)**으로 두고 0으로 그리지 않는다 | 표준점수를 골랐는데 숫자가 보이면 교사가 오해한다. 빈칸은 0점이 아니다(CLAUDE.md) |
| A12 | 탐구1·2 과목명이 같으면(점수가 같든 다르든) A3대로 탐구1 값을 쓰고, 불러온 직후 "탐구 과목 중복 N명" 경고를 띄운다(단계 1 감사 뒤 확정: 같은 과목이 두 번 적힌 것 자체가 자료 오류라 점수가 같아도 알린다) | 자료 오류일 가능성이 높아 사람이 알아야 한다 |

## 1-B. 프로파일(=스키마) 구조와 양식 매칭

**정본 1개 원칙(소유자 결정).** 양식 하나의 모든 사실은 `schema.js`의 그 양식 정의 하나에만 있다.
읽기(파서)·매칭(지문)·내보내기(exporter)는 모두 이 정의에서 파생한다. 별도의 `header-profiles/*.json`이나
`fields.json`·`field-synonyms.json`은 만들지 않는다(이름 해석을 안 하므로 동의어 사전도 필요 없다).

admission-outcomes 프로파일의 **필드 구성**을 따르되, 담는 곳은 `schema.js`다:

```js
daegyohyeop: new FormatSchema({
  id: 'daegyohyeop', label: '대교협', program: 'kcue-csat',   // 기존 id·label 유지
  headerRows: 2,
  fields: { class: 'B', name: 'D', kor_raw: 'K', /* … 기존 매핑 그대로 */ },
  extraColumns: ['E', 'F'], unmappedNote: '…',                  // 신규: 사람이 확인한 미매핑 열
  exportHeaders: [/* 기존 그대로 — 이 양식의 실제 헤더 블록이자 지문의 원천 */],
  customGetters: { /* 기존 그대로 */ },
})
```

- 대상 양식 **5종**: 대교협(`daegyohyeop`), 대교협 가채점(`daegyohyeop_preview`), 유니브(`univcoop`), 김영일(`kimyoungil`), 꿈꾸고(`kkumkugo`).
- **소유자 확인(2026-10-23): 현재 5종의 `fields`·`headerRows`·`exportHeaders`·`customGetters`는 모두 적절하다.** 값은 바꾸지 않는다.
- **지문의 원천 = `exportHeaders`.** `exportHeaders`는 그 양식의 실제 헤더 블록 그대로다(내보내기가 업체 양식과 같은 파일을 만들기 위한 것이므로). 5종 모두 `exportHeaders`의 줄 수가 `headerRows`와 같고 줄마다 열 수가 같다(대교협 2×32, 가채점 3×19, 유니브 2×43, 김영일 1×37, 꿈꾸고 2×32 — 확인함).
  지문은 **저장하지 않고**, 로드할 때 `exportHeaders`를 업로드 파일과 같은 정리 규칙(§1-B 매칭 흐름 1번)으로 정리해 계산한다. 같은 사실을 두 곳에 적지 않으므로 어긋날 수 없고, 소유자가 헤더를 고치면 지문도 자동으로 따라간다.
  가채점 양식의 1행이 전부 빈칸인 것도 실제 양식 그대로이며, 빈 줄도 지문에 들어간다(테스트로 고정).
- 추가되는 것은 `extraColumns`·`unmappedNote`뿐이다(선택 항목, 없으면 비워 둔다). 이를 위해 `FormatSchema` 생성자 인자에 두 이름을 더한다. 생성자의 나머지 — `_idx` 계산과 숫자 필드 getter 자동 주입(schema.js:77–90) — 은 손대지 않는다. `ensureNumericOrZero`(schema.js:495)가 쓰는 `toScore`의 import 위치만 `core/score.js`로 바뀐다.
- `extraColumns`가 `fields`와 겹치지 않는지 테스트한다.
- **승인 게이트:** CLAUDE.md 스키마 규칙에 따라 단계 2에서 `schema.js`를 바꾸는 커밋은 소유자가 diff를 보고 승인한 뒤에 한다.
- 내보내기(`exporter.js:10, 61–66`)는 지금처럼 같은 정의의 열 위치(`_idx`, schema.js:88–90)를 쓴다 — 읽기와 내보내기가 같은 정본을 본다.
- **"숫자로 읽는 값" 판정**(`toScore`, schema.js)은 글자 하나 바꾸지 않고 `core/score.js`로 옮기고, `schema.js`의 `num`/`str`이 그것을 부른다. 새 읽기 경로도 `schema.num`/`str`을 그대로 쓴다.
- 실제 파일과의 대조: 소유자의 실제 파일로 "업로드 헤더 지문 == `exportHeaders` 지문"을 로컬에서 확인하되 결과는 양식별 참/거짓만 남긴다(값·이름 출력 금지, CLAUDE.md 개인정보).
- 두 양식 정의의 지문이 같으면 **테스트에서 실패**시킨다(런타임 수동 선택보다 먼저 잡는다).
- **동일성 테스트:** 5종 각각, 합성 워크북을 옛 경로와 새 경로로 읽어 **레코드가 같고, 내보내기 출력도 같다**(내려받기 `dlBlob` 직전 버퍼를 가로채 비교).

### 매칭 흐름 (사용자 결정 2026-10-23)

1. 프로파일마다 그 `headerRows`로 지문을 내서 비교한다. 지문 = 헤더 줄 수만큼의 헤더 블록 **전체 열을 순서까지** 정리한 뒤 해시한 값. 즉 **헤더 줄 수와 모든 열의 위치·이름이 (정리 후) 일치해야** 자동 선택된다.
   정리 규칙은 admission-outcomes 그대로(headerHash.js:18–52): 줄마다 오른쪽 끝 빈 열 무시, 전각→반각, 연속 공백 하나로. 엑셀 표기 차이일 뿐 다른 양식이 아니기 때문이다.
   셀 경계가 뭉개져 다른 헤더가 같은 지문이 되지 않는지(구분자 충돌) 테스트를 둔다.
   정리 규칙 목록에는 폭 없는 문자 제거(headerHash.js:24)도 포함한다.
   **병합 셀:** `exportHeaders`는 병합 범위에서 주인 칸(왼쪽 위)이 아닌 칸을 `''`로 적는다. 지문 입력에서는 **읽기 경로와 상관없이 병합 범위의 주인 칸이 아닌 칸을 `''`로 만든다.**
   SheetJS 경로(main.js:76–79, `defval: null`)는 주인이 아닌 칸을 `null`로 돌려주고, 지문 함수가 `null`을 `''`로 바꾼다. 엑셀이 아닌 도구로 만든 파일은 주인이 아닌 칸에 값이 남을 수 있으므로 SheetJS 경로에서도 `!merges` 범위로 같은 처리를 한다. ExcelJS 경로는 병합된 칸에도 주인 값을 돌려주므로(가로·세로 모두) `cell.isMerged && cell.master !== cell`이면 `''`로 바꾼다.
   이 처리는 **지문 전용 헤더 추출 함수**에서만 한다. 본문 읽기용 `exceljsTo2DArray`는 바꾸지 않는다(레코드 동일성 테스트에 영향이 가지 않게).
   테스트: 5종 각각, 가로·세로 병합 헤더를 가진 합성 파일을 **ExcelJS와 SheetJS 두 경로로 읽은 지문 == `exportHeaders` 지문.** 왼쪽에 빈 열이 있는 파일도 A1 고정 처리로 열 위치가 유지되는지 확인한다.
   실제 파일 대조도 두 경로 각각 양식별 참/거짓만 남긴다.
2. 자동 선택은 **정확히 한 프로파일만 맞을 때만**이다. admission-outcomes의 `matchProfile`(profile.js:234)은 헤더 줄 수를 작은 것부터 시도해 **처음 맞은 것을 바로 반환**하므로, **후보 전부를 모은 뒤 판정하도록 고쳐서 이식한다.** 지문이 같은데 매핑이 다른 경우(`conflict`)도 이름 해석이 아니라 수동 선택으로 보낸다. 여러 프로파일이 맞으면(예: 2줄 양식과 3줄 양식의 앞 두 줄이 같은 경우) 자동 선택하지 않고 고르게 한다. 대교협·대교협 가채점을 서로 구분하는 테스트와, 둘 이상 맞을 때 자동 선택하지 않는 테스트를 둔다.
3. 자동 선택된 뒤에도 값 범위 교차검증(백분위 0–100, 등급 1–9, 원점수 0–100)을 하고, 어긋나면 경고한다.
4. 맞는 프로파일이 없으면 **지금처럼 양식 선택 버튼**을 준다.
5. **자동 선택이든 아니든 사용자가 양식을 바꿀 수 있다.** 현행처럼 **앞 5줄 미리보기**를 양식의 열 이름과 나란히 보여 주고 확인받는 흐름을 유지한다. 자동 선택은 기본값을 정해 줄 뿐이다.
6. 이름 해석(`resolveColumns`) 폴백은 이번 범위에 넣지 않는다(§6 미리 만들지 않기). 새 양식은 `schema.js`에 양식 정의 하나를 추가해 대응한다.
   이식한 매칭 코드에 이름 해석을 부르는 호출이 남지 않게 하고, `needsFallback`의 뜻은 "수동 선택"으로 바꾼다.

## 2. 우선순위와 이유

위험이 큰 것부터, 그리고 **화면 없이 테스트로 검증할 수 있는 것**부터 한다.
UI 재작성은 가장 크지만 가장 덜 위험하므로(틀리면 눈에 보인다) 뒤로 둔다.
조용히 틀리는 값(잘못 매칭된 양식, 잘못 이어진 학생, 잘못 계산된 석차)이 가장 위험하다.

| 순위 | 항목 | 이유 |
|---|---|---|
| P0 | 회귀 기준선 고정 | 갈아엎기 전에 현재 출력(파싱 결과·통계·순위)을 골든 테스트로 묶는다. 이게 없으면 재작성의 정답을 모른다 |
| P1 | R4 탐구평균 합산 | 범위가 작고 계산 핵심이다. 현 앱에서도 바로 쓸모가 있고, 이후 모든 화면이 이 함수를 쓴다 |
| P2 | R3 자동 매칭(입력 계층) | 잘못 매칭이 실제로 일어났던 위험. 다회차의 전제(회차마다 양식이 다름) |
| P3 | R2 데이터 모델(회차·학생 연결) | UI와 분리된 순수 모듈로 먼저 만든다 |
| P4 | R1 새 프론트엔드 | 위 코어 위에 새로 쌓는다 |
| P5 | 추이 화면(전교·학생) | 새 UI의 마지막 조각 |

## 3. 아키텍처 방향

"처음부터 다시"는 **UI 층만** 처음부터다. 계산 규칙(빈칸≠0, 전부 0이면 미응시, 공동순위, 숫자 판정)은
지금 코드와 테스트에 녹아 있는 자산이므로 코어로 **옮기되 다시 발명하지 않는다.**

```
src/
  core/      score.js(toScore·blankIfAllZero), rank.js(공동순위·상위N), aggregate.js(국+수+탐구평균)
  ingest/    files.js(xlsx·zip·암호), headerBlock/headerHash/profile  ← admission-outcomes에서 이식(resolveColumns 제외)
             toRecord.js(양식 정의 → 학생 레코드, `schema.num`/`str` 사용)
  schema.js  양식 정의의 유일한 정본(열 매핑·지문·헤더 줄 수·내보내기 헤더·getter)
  exams/     examStore.js(회차 목록, 정렬, 저장/불러오기 .json), identity.js(회차 간 학생 연결)
  ui/        topbar, upload, table(GridTable 이식), report/*, trend/*, student/*
```

- 프레임워크 없이 vanilla JS 유지(두 프로젝트 모두 그렇다). Tailwind는 admission-outcomes에 맞춰 v4로,
  Vite도 맞춘다 — 단 이는 P4에서, 별도 커밋으로.
- 전역 `ST` 상태 대신 `examStore`가 단일 출처. 리포트 함수는 `(students, options)`를 받는 순수 함수로 바꾼다.
- 암호 걸린 xlsx 해제(`xlsx-decrypt.js`), SHA(`sha.js`)는 그대로 가져간다. **암호 해제가 없어지면 회귀다.**
  직접 올린 파일이든 zip 안의 파일이든 같은 경로를 거친다: OLE2 바이트면 먼저 `xlsx-decrypt`로 해제를 시도하고(현행 main.js:240과 같은 동작), 안 되면 xls로 판정한다.
  admission-outcomes `files.js`는 OLE2를 xls로만 판정하므로(files.js:45) 이 분기를 넣어 고쳐서 이식한다.
- 내보내기(`exporter.js`)는 같은 정본(`schema.js`)의 열 위치를 계속 쓴다. 동작은 바꾸지 않는다.

## 4. 단계 (각 단계 = 독립 커밋 + `npm run ci` 통과 + 승인 게이트)

모든 단계는 `migration/multi-exam` 브랜치에서. master 병합·태그·배포는 전체 완료 후 소유자가 결정한다.

**단계 0 — 기준선** (코드 동작 변화 없음)
- 기존 테스트 전량 통과 확인. 합성(가상) 샘플 워크북으로 **5종 양식** 각각의 파싱 결과·통계·순위·내보내기 출력 스냅숏 테스트 추가.
  "모든 점수 0 → 미응시"(`blankIfAllZero`)와 `sumParts` 예외, 그리고 둘이 겹치는 경우(공통 0·선택 빈칸·나머지 전부 0)도 스냅숏에 포함한다.
  상위 N 표의 동점 처리(report-render-topN.js:41–46)와 2·3차 정렬(반·번호) 순서도 포함한다.
- 실제 `*_test.xlsx`는 집계(행 수, 매칭 성공 여부, 값 범위)만 로컬 확인, 저장소·로그에 값 금지.

**단계 1 — R4 탐구평균** (결정 2)
- 첫 커밋: **CLAUDE.md 점수 해석 원칙의 4과목 합 문구 수정**(결정 2, §1-A).
- `inquiryAvg(s, basis)`: §1-A A1·A3 규칙.
- `compositeScore(s, basis, {includeNoInquiry})` = 국 + 수 + 탐구평균; 국·수 중 하나라도 없으면 null.
  탐구 0개면 기본 null(제외 인원 집계), 옵션이 켜지면 국 + 수.
- 리포트에 제외 인원 문구와 "탐구 미응시 학생도 포함" 체크박스.
- `report-cache.js:75`, `report-modal.js:118`, 수능최저 전교 석차(`_getScoreSum`, report-csat-sum.js:69·128) 세 곳이 같은 함수를 쓰게 한다.
  `_getScoreSum`의 빈칸→0 제거는 별도 커밋(§1-A A9).
- 수능최저 등급 n합(sum2~sum5)은 그대로 둔다.
- 테스트: 기준 값이 없는 회차에서 §1-C 화면의 숫자 자리가 모두 `—`이고 다른 기준 값이 새지 않음, A10의 "없음끼리 같음"이 공동순위 1·1·3과 맞물리는 예, 탐구 1/2/0과목(옵션 켬/끔), **탐구1 빈칸·탐구2만 있음**, 같은 과목 중복, 기준 혼합(탐구1 표점·탐구2 원점수만), **원점수만 있는 회차의 수능최저 석차**, 빈칸 vs 0, 평균 소수 유지, 동점 1·1·3.
- 이 단계는 **현 앱에 먼저 적용**해 독립 릴리스할 수 있다(원하면 master로 별도 반영).

**단계 2 — 입력 계층 이식** (결정 1)
- admission-outcomes의 `files.js`(zip 포함), `headerBlock`, `headerHash`, `profile` 이식. `matchProfile`은 §1-B 2번대로, `files.js`는 §3의 암호 해제 분기를 넣어 고쳐서 이식한다.
- 테스트: 직접 올린 암호 파일, **zip 안의 암호 파일**, 암호가 틀린 파일.
- 기존 `SCHEMAS` 5종에 `extraColumns`·`unmappedNote`를 더하고 지문은 `exportHeaders`에서 로드 시 계산한다(§1-B, 기존 값 불변, 커밋 전 소유자 diff 승인). **동일성 테스트**: 레코드와 내보내기 출력이 같다.
- 매칭 정책: §1-B 매칭 흐름. 수동 선택과 5줄 미리보기는 유지한다.
- `sumParts`(공통+선택 빈칸 0 처리) 예외는 그대로 유지.

**단계 3 — 회차·학생 모델**
- `examStore`: `{key, order, formatId, fileName, fileHash, students[]}` 목록(formatId = schema.js 양식 id, 프로파일=스키마). 키 중복 금지, 초기 순서 제안, 순서 이동, 삭제.
- `identity.js`: 결정 5의 키로 같은 학년 회차 간 연결; 모호하면 잇지 않고 미매칭 목록. 학년 간 대응표 입력 자리만 둔다.
- `.json` 저장/불러오기(원본 엑셀 미포함). 담는 것: 파일 형식 버전, 회차별 `key`·`order`·프로파일 id·파일 해시(SHA), 학생 레코드, 체크박스 등 화면 옵션.
  저장할 때 "이름·성적이 담긴 개인정보 파일" 경고를 띄운다. `.gitignore`에 프로젝트 파일 패턴을 추가한다.
- 한 회차 안에서 식별 키가 겹치는 학생(전학생 등)은 그 회차 안에서도 잇지 않고 확인 대상으로 둔다.
- 순수 함수 + 테스트만, UI 없음.

**단계 4 — 새 프론트엔드 골격**
- 상단바(회차 목록·현재 파일·초기화 항상 보임), 업로드(다중 파일·zip·드래그, 파일별 매칭 결과와 회차 키 입력란),
  회차 순서 편집(위/아래 이동),
  GridTable 이식으로 학생 목록.
- 기존 index.html은 이 단계에서 교체. 기능 동등성 체크리스트(아래 §5)로 확인.

**단계 5 — 단일 회차 리포트 재구현**
- 기존 리포트(과목 통계, 분포, 상위 N, 수능최저, 학생 모달, 인쇄)를 새 UI에서 회차 선택형으로.

**단계 6 — 추이 화면**
- 전교: 회차별 평균·분포·급간 비율 추이(Chart.js).
- 학생: 검색 → 회차별 과목 원/표/백/등급, 합산 석차 추이, 인쇄.

**단계 7 — 정리**
- README·CLAUDE.md 갱신, 죽은 코드 제거(`report.js`의 `resize` 리스너는 CLAUDE.md대로 새 리포트 쪽에 **보존**한다), 버전·태그는 병합 시점에.

## 5. 기능 동등성 체크리스트 (단계 4·5 완료 조건)

현 앱의 모든 기능을 단계 5 전에 목록화해 하나씩 체크한다(`actions.js`의 동작 목록 전수 포함):
양식 5종 읽기·수동 선택·5줄 미리보기, 암호 파일, 샘플 데이터, 원/표/백 기준 전환,
